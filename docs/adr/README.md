# 架构决策记录（ADR）

本目录记录**已经定下、且推翻需要理由**的架构决策。

## 什么情况下该写一篇 ADR

- 这个决定会影响多个模块
- 存在一个"看起来更显然"的备选方案，而我们没选它
- 将来有人可能会想改掉它

## 格式

```markdown
# NNNN. 决策标题

- 状态：已接受 / 已废弃 / 被 NNNN 取代
- 日期：YYYY-MM-DD

## 背景
## 决策
## 备选方案与被否决原因
## 后果
```

## 规则

1. **推翻一条 ADR 要新增一篇 ADR**，说明为什么。
   直接改代码而不留记录，等于让后人重新踩一遍已经踩过的坑。
2. **"后果"一节必须包含代价。** 只写收益的 ADR 是宣传，不是决策记录。
