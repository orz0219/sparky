# 0003. 共识 = 显式分歧台账，而非 LLM 自述一致

- 状态：已接受
- 日期：2026-10-12

## 背景

这是本项目**最关键**的一个决策：怎么判断"讨论完了"？

朴素做法是问模型：

```
你：大家达成一致了吗？
模型：经过充分讨论，我们已经达成一致。最终方案是……
```

这段对话**无论是否真的一致都会发生**。原因：

1. LLM 有强烈的**迎合倾向**（sycophancy）—— 你问"同意了吗"，它倾向说"同意了"
2. "一致"语义模糊，模型可以把"没人明确反对"合法地解释成一致

结果是：一个看起来完美、实则未经验证的结论，**带着虚假的确定性**。
对"设计工具"这种产物来说，这比没有结论更危险。

补充背景：LLM 的默认倾向是附和。你不强制它反驳，N 个 Agent 只会产出
N 份措辞不同的赞成票。

## 决策

**共识 ≠ 大家同意；共识 = 没有未解释的反对意见。**

具体落地为四条：

1. **分歧台账（Ledger）是收敛判定的唯一依据。**
   每个 Agent 的发言必须包含对具体分歧的明确回应
   （`{disagreement_id, action: support|rebut|amend, reason}`），
   由主持人登记为带 ID 的 `Disagreement`。

2. **收敛判定是纯函数。** `consensus.decide(ledger, round, budget, cfg) -> Decision`
   —— 无 IO、无 LLM、无随机。同样的输入必然给出同样的输出。
   终止条件是**控制流**，不是创作。

3. **分歧可以降级为取舍（tradeoff），但不许被抹掉。**
   一项分歧只要写明"什么条件下该反过来选"，就算收敛。
   台账**只增不删**，被否决的方案要进最终文档。

4. **真正的死锁如实标注为未决问题，交给人类。**
   优先尝试降级为条件分歧；连条件都写不出来的价值观冲突，就置顶标记
   `⚠️ 未决` 并附双方原始论据。

配套：**零分歧是失败信号**，会在文档顶部插入显著告警
（见 [../consensus.md](../consensus.md) §6）。

## 备选方案与被否决原因

| 方案 | 否决原因 |
|---|---|
| 让 LLM 判断"是否达成一致" | 迎合倾向 + 不可复现 + 模型可以无限拖延 → 成本不可预测 |
| 投票表决（多数决） | 设计问题不是投票问题。3:2 的多数决会把少数派的关键洞察直接丢弃，而那些洞察往往正是最有价值的 |
| 固定轮数后强行收敛 | 无法区分"真收敛"与"聊累了"，且可能在第一轮就已达成的简单问题上浪费轮次 |
| 要求 100% 一致才能结束 | 会让最顽固的 Agent 拥有无限否决权，讨论永远结束不了 |
| 让用户来判断何时结束 | 用户的困难正是"没有头绪"，让他来判断"聊够了没有"是把问题还给他 |

## 后果

**收益**：

- 终止条件**可复现、可测试、成本可预测**。`consensus.py` 的 6 个分支能被单测全覆盖
- 被否决的方案被保留下来 —— 这是本工具相对"问一次大模型"最实在的增量
- 未收敛时如实告知，用户知道哪几项要自己拍板
- 台账的条数与最终文档的取舍/未决条目数**必须一致**，
  这构成一道**防篡改**检查（LLM 无法凭空捏造或悄悄抹掉）

**代价（必须承认）**：

1. **"没有未解释的反对意见"比"大家同意"弱。**
   一项被降级为 tradeoff 的分歧，实际上并没有被解决，只是被**框定**了。
   对于高风险决策场景，这个门槛可能太低。
2. **依赖 Agent 产出的结构化质量。** 如果模型输出不了合法的 `responds_to`，
   回应义务就落空了。当前的应对是：解析失败即视为弃权并**如实记账**，
   连续弃权 2 轮移出讨论 —— 但一个全员弃权的会话产出的文档质量很差。
3. **停滞检测的粒度未定**（逐字太严、语义比较要调模型）。
   当前用 `(立场方向, closes, opens)` 三元组，是拍脑袋定的。
4. **`force_stop` 的会话数量可能偏多**，因为 max_rounds 默认只有 4。

**触发重新考虑的条件**：

- 若实测中 `force_stop(stagnation)` 占比很高，说明停滞判据过于敏感
- 若用于高风险决策（医疗 / 金融 / 安全），需要提高共识门槛并引入人工裁定环节

**推翻本 ADR 需要**：新增一篇 ADR，说明为什么接受"不可复现的终止条件"。
