# 0004. 信息面隔离：每个 Agent 看到不同的上下文

- 状态：已接受
- 日期：2026-10-12

## 背景

多 Agent 讨论**最容易做错**的地方，是把所有参考资料塞进每个人的 prompt，
然后期待他们观点不同。

结果必然是**同质化**：N 个 Agent 对同一份输入做 N 次采样。
这不是讨论，是重复采样。用这种方式做出的工具，本质上就是"多开几个
ChatGPT 窗口然后手动复制粘贴"，只是自动化了复制粘贴这一步。

更糟的是，同质化会让讨论**看起来很热闹但毫无信息量** ——
每个人说的都对，每个人都同意别人，最后产出一份谁都没意见的空洞文档。

## 决策

**每个 Agent 在调研阶段拿到不同的上下文切片。**

公共层只有 `Brief` 的目标 / 约束 / 非目标（这是大家必须一致的部分），
其余全部按人设切分：

| 维度 | 每个人拿到什么 |
|---|---|
| 追问清单 | **按设计维度生成**，每人回答的是自己那一组问题 |
| 检索词 | **由人设自己生成**（取决于他的视角） |
| 本地资料 | 从 `--context-dir` 按维度相关性**分配**，不搞人手一份 |
| 检索预算 | 每人独立的 `budget {searches, tokens}` |

隔离规则（实现时为硬约束，需显式断言守住）：

1. **S2 阶段，任何人的 `StanceMemo` 不得进入他人的 prompt。**
   这是最关键的一条 —— 违反它整个工具就退化了。
2. 讨论中的"互相看见"**只发生在 S3**，且只交换**立场**，
   不交换各自的原始推理链。这既控制上下文膨胀，也**保留信息差作为张力来源**。
3. 轮内只读上一轮的**快照**，不读本轮他人正在生成的输出。

## 备选方案与被否决原因

| 方案 | 否决原因 |
|---|---|
| 全员共享全部上下文 | N 次采样同一输入，讨论必然同质化 —— 这正是要避免的 |
| 全员共享 + 在 prompt 里要求"请从不同角度" | 靠提示词制造差异，效果远弱于真正的信息差，且不可验证 |
| 共享立场 + 共享完整推理链 | 上下文成本爆炸（每个人的推理链都很长），且会让所有人迅速趋同 —— 看到别人的完整推理后很难不跟着走 |
| 引入向量库做检索隔离 | 对"一次会话"来说过度设计。按维度分配文件已经足够，且不需要额外基础设施 |
| 给每个 Agent 不同的基础模型 | 能降低同质化，但架构上更重（多套密钥/计费）。已作为扩展点保留（[../architecture.md](../architecture.md) §8） |

## 后果

**收益**：

- Agent 之间产生**真实的信息差**，这是讨论有内容的前提
- 每人检索预算独立 → 成本可控且可预测
- 最终文档的「信息来源」附录能列出**每人用了什么**，而不是笼统一个参考列表

**代价（必须承认）**：

1. **信息不足会导致说空话。** 一个人只看到自己那条信息线，
   可能因为资料不够而给出浮于表面的意见。当前没有"信息充分性自检"机制
   （见 [../design.md](../design.md) §11 未决问题 3）。
2. **实现复杂度显著上升。** 需要显式维护每个 Agent 的上下文边界，
   并写断言防止串味。这比"把所有东西塞进 messages"麻烦得多。
3. **隔离可能过度。** 如果某条关键信息只被分配给了一个人，
   而这个人恰好是弃权/失败的那个，整场讨论就会缺掉这块。
4. **调试变难。** 每次 LLM 调用喂了什么都不一样，
   必须依赖调用前落盘的上下文快照来排查（见
   [../architecture.md](../architecture.md) §4）。

**触发重新考虑的条件**：

- 若实测发现讨论"浮于表面"（分歧都停留在措辞而非实质），说明隔离导致
  信息不足，可放开为「共享立场 + 可点名索取依据」
- 若某个 Agent 频繁因信息不足而弃权，说明分配算法有问题，需要按维度
  相关性重新校准

**推翻本 ADR 需要**：新增一篇 ADR，并附上"信息面共享后讨论质量未下降"
的实测对比数据。
