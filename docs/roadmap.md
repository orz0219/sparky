## M1 · 最小可用闭环 ← **已完成（2026-10-12）**

**目标**：跑通 `一句话 → 文档`，先把"能产出合规文档"这件事验证掉。

**范围**：S0 立案 → S1 组阁 → S2 调研 → S5 定稿，**先跳过讨论**。

**为什么先跳过 S3/S4**：讨论与收敛是最复杂、最容易过度的部分。
先证明"维度抽取 + 人设生成 + 模板装配"这条主干能产出合格文档，
再往上加讨论。否则一旦出问题，分不清是主干坏了还是讨论坏了。

**验收**：
- [x] `python3 -m sparky "..."` 能跑完，退出码 0
- [x] 产出文档通过 [output-spec.md](output-spec.md) §3 的**全部**检查项
- [x] 文档里至少 3 个维度是用户原话中**没有**的
- [x] 人设数量落在 3–7，且必含一个 adversary
- [x] 缺 `DEEPSEEK_API_KEY` 时**立即报错退出**，退出码 3
- [x] 会话目录含 `meta.json` / `brief.json` / `personas.json` / `transcript.jsonl` / `design.md`
      （另有 `stances/` 与 `llm-calls/`，见 [architecture.md](architecture.md) §4）
- [x] 无 `--web` 时终端可读
- [x] 一次真实会话的完整产物已收进
      [`examples/01-podcast-transcriber/`](../examples/01-podcast-transcriber/)：
      38542 字文档、18 次调用、156976 token、通过全部 9 项校验

**不做**（也确实没做）：多轮讨论、联网检索、断点续跑、单文件打包、本地网页。

**实现中的偏差记录**（详见 [architecture.md](architecture.md) §1 末节）：
- 新增了 `errors.py` / `models.py` / `render.py` 三个模块 —— 设计定稿时没给它们安排归属
- `llm.py` 在 M1 是**非流式**的。`turn.token` 打字机效果属于 M3，
  届时加一个与之并列的 `stream()` 即可，不影响现有接口
- `--web` / `--port` / `--resume` **刻意不在 M1 暴露** —— 暴露一个只会报错的开关
  比不暴露更糟

**实现中确认的两个真实问题**：
1. **推理模型的输出预算会被 reasoning 吃光**：`max_tokens=40` 时
   `completion_tokens` 全是 reasoning，正文为空。已加下限校验与显式检测。
2. **提示词占位符不能用 `{x}`**：提示词正文里全是 JSON 花括号。
   最终用 `${x}` + 位置限定参数（见 [configuration.md](configuration.md) §7）

## M2 · 讨论与收敛 ← **已完成（2026-10-12）**

**目标**：把最核心的机制装上 —— 真的吵起来，并且知道什么时候停。

**范围**：S3 交锋 + S4 收敛 + 分歧台账。

**验收**：
- [x] 至少一次真实会话中产生 ≥ 2 项分歧，且分歧台账非空
- [x] 每轮 `Turn` 都含非空 `responds_to`（弃权除外，弃权被如实记录）
- [x] 收敛判定 `consensus.decide()` 为**纯函数**，单测覆盖全部 6 个分支
- [x] `--max-rounds 1` 时确实只跑一轮
- [x] 定向加轮只召集当事双方（`_pick_participants` 单测覆盖）
- [x] 零分歧的会话会在文档顶部插入「未产生实质分歧」告警
- [x] S2 阶段断言：任何人的 `StanceMemo` 不出现在他人 prompt 中
- [x] 未收敛时段落标注 `⚠️ 未决`，条数与台账 `stalemate` 数一致
- [x] 定稿 §5 取舍台账 / §8 未决问题 / 附录 C 全部渲染真实台账数据

**实现中的三处设计微调**（详见 [consensus.md](consensus.md) §3.2 §5）：
1. 收口时 remaining `open` → `stalemate`，**不是**原文写的"强制降级为 tradeoff"
   —— 取舍的条件必须由模型给出，代码硬填就是编造决策依据
2. 定向加轮改成**每人一次调用覆盖他牵涉的所有分歧**，而不是每 (分歧, 当事人) 一对
   —— 一个人一轮里只该有一个声音，拆开会有自相矛盾的风险
3. `prompts/turn.md` 删掉了「普通后续轮」块 —— 后续轮永远是定向加轮，
   留着它就是死代码

**测试**：182 个单测（M1 是 104），新增
[`tests/test_consensus.py`](../tests/test_consensus.py)（6 分支 + 判断顺序 + 纯函数性）、
[`tests/test_debate.py`](../tests/test_debate.py)（台账状态机的每条规则）、
[`tests/test_turn_prompts.py`](../tests/test_turn_prompts.py)（提示词组装的集成级防漂移）。

**不做**：联网检索、断点续跑、单文件打包、本地网页。

## M3 · 本地网页 ← **已完成（2026-10-12）**

**目标**：能看着它们吵。

**范围**：`server.py` + `web/*` + SSE 全事件 + 流式调用。

**验收**：
- [x] `python3 -m sparky "..."` 自动打开浏览器，讨论**逐字**出现
- [x] 刷新页面后，历史事件被补发，界面恢复到当前状态
- [x] 人设卡 / 讨论流 / 分歧台账 / 轮次时间线四块区域都随事件更新
- [x] 端口占用时**报错退出**，不静默换端口（这一条在真实场景里被验证了：
      旧进程还占着端口时，服务拒绝启动而不是偷偷换端口）
- [x] 前端零外链：断网后页面仍能正常工作（除 LLM 调用）
- [x] 前端共 **780 行**，无任何构建步骤
- [x] `session.error` 事件显示红条且**不清空**已有内容
- [x] 已在浏览器里**目视确认**（用 `tools/demo_server.py` 的合成事件回放）

**实现时确定的三件事**（详见 [web-ui.md](web-ui.md) §0）：
1. 打字机效果靠发言 schema 里**第一位的 `say` 字段** + 后端的增量抽取，
   而不是把裸 JSON 逐字显示出来
2. `turn.token` **不落盘** —— 一次发言上千条，写进审计日志会让它不可用
3. 前端按 `requestAnimationFrame` 批量渲染，不逐个 token 写 DOM

**顺带修掉一个真实 bug**：`allow_reuse_address=False` 会让服务停掉之后
端口在一分钟内无法重用（重启直接失败）。那是把 `SO_REUSEADDR`
误解成了"防止端口被抢占" —— 它只管 TIME_WAIT 残留。

**不做**：联网检索、断点续跑、单文件打包。

## M3.1 · 插话 + 阅读体验重做 ← **已完成（2026-10-12）**

**触发**：实际用了一遍，用户提了两个问题 ——「我没法插话」与
「页面 UI 比较乱，看着很难受」。两条都成立。

**验收**：
- [x] 随时可插话，`POST /interject` 收到即广播
- [x] 插话在**轮间**注入下一轮提示词，不破坏并发不变量
- [x] 界面立即可见，并标明"已记下 / 已在第 N 轮送达"
- [x] 侧栏有**永不折叠**的"你的插话"索引
- [x] 插话写进文档附录 C（含未送达的）
- [x] 阅读体验按四个诊断重做（见 [web-ui.md](web-ui.md) §2.5）
- [x] 目视确认 + 端到端实跑验证专家真的读到了

**实跑验证**：一次真实会话中，专家不但照做，还指出**委托人的两条要求
互相打架** —— 说明提示词里"冲突时说出来，不要默默接受"那句起作用了。
如果没有它，插话会变成"所有人立刻改口"，比不插话更糟。

**顺带修掉三个真实 bug**（都是"实际跑一遍"才暴露的）：
1. 插话在提示词里**出现两遍** —— `__main__` 与 `debate` 各 append 了一次
2. `x-opencode-session` 用了含中文的 session_id，HTTP 头 latin-1 编码直接崩
3. 演示夹具漏了 `summary` 字段，发言正文整段空白

## M3.2 · 提案工作台 ← **已完成（2026-10-13）**

**触发**：实际用了几次之后，用户提的问题很直接 ——
「我这个网页上没法看到具体的已发起提案列表及相关内容」，
具体列了三条：历史提案、当前提案、新建提案。三条都成立。

**目标**：网页从"一次运行的查看器"变成**提案工作台**。

**验收**：
- [x] `python3 -m sparky`（不给想法）起工作台，进程服务到 Ctrl-C
- [x] 清单列出 `--out` 下的全部提案：状态、时间、人数、轮数、分歧、文档字数
- [x] 点开任意一份历史提案，**重放 `transcript.jsonl`** 还原整场讨论，不重新跑模型
- [x] 「设计文档」页签渲染最终 `design.md`（服务端 `markdown.py`，含转义）
- [x] 页面上直接新建提案：表单 → `POST /api/proposals` → 后台线程跑流水线
- [x] 停止 / 插话都按**提案**操作，不再是一个全局的"当前会话"
- [x] 进程重启后，之前"进行中"的提案如实显示为「未跑完（进程已退出）」
- [x] `meta.json` 损坏的会话显示为「损坏」并写明原因，不影响其余提案
- [x] 命令行用法**完全没变**：`python3 -m sparky "想法"` 与从前一致
- [x] 目视确认三种提案 + 设计文档 + "连接结束了但没收口"这条路径

**实现中的四处关键判断**（详见 [adr/0005](adr/0005-proposal-workspace.md)）：

1. **流水线从 `__main__` 抽进 `pipeline.py`** —— 不抽的话工作台只能复制一份，
   两份迟早漂移，而漂移的后果是"命令行跑得好好的，网页上跑出来的不一样"
2. **`EventHub` / `InterjectionQueue` 从 `server.py` 挪进 `events.py`** ——
   工作台属于编排层，而编排层不许 import `server`；
   这两者本来就不含 HTTP 概念，挪走比给禁令开例外好
3. **`server` 不 import `workspace`**，只认一个 `ProposalApi` 结构协议 ——
   于是测试可以塞一个假工作台进来，不必起流水线
4. **看历史不重新跑模型**：重放出来的事件序列与实时讨论**完全同形**，
   所以前端一行都不用改

**顺带修掉三个真实 bug**（都是"实际点一遍"才暴露的）：
1. **`EventSource` 断开后会自动重连并重放** —— 页面上的每一段发言都多出一份。
   修法是前端在 `onerror` 里**显式 `close()`**（后端已明确表示没有实时流了，
   重连在构造上就没有意义）
2. **业务错误事件曾经叫 `error`，与 `EventSource` 的 DOM 事件撞名** ——
   前端的 `addEventListener("error", …)` 会同时收到浏览器自己发的连接错误，
   `JSON.parse(undefined)` 抛异常，把真正的错误盖掉。改名为 `session.error`
3. **`/api/*` 的失败响应是纯文本，而前端对每个响应都调 `r.json()`** ——
   真正的原因被解析错误盖掉，用户看到 "Unexpected token"。
   现在 `/api/*` 成功失败**都是 JSON**

**代价**：前端从 1200 行涨到约 1800 行（护栏上调，理由写在
[web-ui.md](web-ui.md) §6）；允许多份提案并发跑，没做队列。

**不做**：联网检索、断点续跑、单文件打包。

## M4 · 检索、续跑与分发

**目标**：从"能跑"到"好用"。

**范围**：信息检索接入 + `--resume` + `tools/build_single_file.py`。

**验收**：
- [ ] 有检索能力时，各人设使用**不同**检索词，且来源逐条进附录 B
- [ ] 无检索能力时，附录 B 显式声明「本次未使用外部检索」
- [ ] `--resume <session_id>` 能从任意中断点续跑，不重复已完成的调用
- [ ] `tools/build_single_file.py` 产出 `dist/sparky.py`，**该文件零第三方依赖**、
      前端资源已内联，可单独拷走运行
- [ ] 会话结束后可导出 `report.html`（单文件，无外部请求）

## 成本预算（全程）

按 5 人 × 3 轮估算，单次会话约 **20–40 次 LLM 调用**。
用 `--model-fast` 跑例行发言、`--model-strong` 跑组阁与定稿时，
单次会话成本应控制在**几毛钱**量级。M1 完成时实测一次并记录真实数字。
