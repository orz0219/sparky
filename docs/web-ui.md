# 前端设计

> 表现层。上游是 [architecture.md](architecture.md) §5 的事件协议。

---

## 1. 形态选择

**选了：本地网页（标准库 HTTP 服务）+ 终端纯文本兜底。**

| 候选 | 否决理由 |
|---|---|
| 纯终端 TUI | 多 Agent 多轮讨论挤在终端里，人设卡、分歧台账、时间线三者无法并置 |
| 全栈 Web（React + 构建） | 需要 npm / 打包器 / node_modules，违背零依赖 |
| Tauri 桌面应用 | 需要 Rust 工具链 + 前端构建，本项目最重的选项 |
| **本地网页 + 原生 JS** | **零构建、零依赖，且能做到实时气泡流** |

启动后自动打开 `http://127.0.0.1:8765`。
不加 `--web` 则完全不启动服务器，直接往 stdout 打文本时间线 ——
这样在 SSH 里、CI 里、以及"只想快速跑一下"时都能用。

## 2. SSE 事件协议（对外）

端点：`GET /events`（`text/event-stream`）

```
event: turn.token
data: {"persona_id":"p3","delta":"我认为"}

event: disagreement.open
data: {"id":"x1","topic":"是否内置离线模型","parties":["p2","p3"],"status":"open",...}
```

- 事件类型与字段**完全复用** [architecture.md](architecture.md) §5 的表，不另造一套。
- 连接建立后**先补发历史事件**（从 `transcript.jsonl` 重放），再进入实时流。
  这样中途刷新页面不会丢失已发生的讨论。
- 服务端每 15 秒发送一次 `: keepalive` 注释行防连接超时。
- 会话结束后发送 `session.end` 并主动关闭连接。

**一条硬约束**：任何事件都**不得**携带密钥、base_url 或完整 prompt。
前端需要的是"发生了什么"，不是"内部怎么调的"。

### 2.1 为什么能直接复用内部事件

因为 [architecture.md](architecture.md) §2 规定编排层不认识 HTTP、
表现层不认识 LLM，两者只通过事件总线通信。
SSE 只是把内存总线上的同一种结构序列化出去。
**不需要维护两套协议** —— 这也是分层约束最直接的收益。

四块区域各自对应一类事件：

| 区域 | 消费的事件 | 回答的问题 |
|---|---|---|
| 参会人设 | `panel.ready` / `recon.*` | **谁**在开会 |
| 讨论流 | `turn.*` | 他们**说了什么** |
| 分歧台账 | `disagreement.*` | 哪些**还没谈拢** |
| 底部时间线 | `round.*` / `convergence.*` | **进行到哪**了 |

## 4. 交互

| 操作 | 行为 |
|---|---|
| 顶部「⏹ 停止」 | 发送 `POST /stop`，当前轮结束后优雅停止并直接进入定稿 |
| 点击某张人设卡 | 过滤讨论流，只看这个人说的 |
| 点击台账某条 | 讨论流滚动到该分歧的首次提出处 |
| 点击某轮标题 | 折叠/展开该轮 |
| `doc.ready` 之后 | 顶栏出现「打开 design.md」与「导出单文件报告」 |

**默认不做**：不做中途插话（这会破坏"每轮只读上轮快照"的并发不变量，
见 [consensus.md](consensus.md) §2.1）。用户想追加信息，请开新会话。

## 5. 状态与容错

| 情况 | 前端行为 |
|---|---|
| SSE 断开（进程崩了） | 顶部红条：「连接已断开。已落盘内容保留在 .sparky/sessions/…」 |
| 刷新页面 | 服务端先补发历史事件，界面恢复到当前状态 |
| `error` 事件 | 红条显示阶段与消息，保留全部历史内容（不清屏） |
| `turn.token` 洪水 | 按 `requestAnimationFrame` 批量渲染，**不**每 token 触发一次 layout |
| JS 自身异常 | `window.onerror` 捕获后在顶部显示错误条，**不留白屏** |

**一条原则**：前端永不隐藏已发生的事实。出错也好、未收敛也好，
用户必须能看到完整信息。这和后端"失败就说失败"是同一条原则的两面。

## 6. 零构建的约束

写前端时遵守以下限制，否则"零构建"就是句空话：

- **不许用** npm、TypeScript、JSX、任何打包器、任何 CDN 外链。
- 只用原生 `<script>` / `<style>`，能用 CSS 的就不用 JS。
- 事件流手写解析（SSE 格式极简：`event:` / `data:` / 空行分隔）。
- 目标：`index.html` + `app.js` + `style.css` 三个文件，总计 1000 行以内。
- 不引入任何字体文件与图片资源，图标用 Unicode 字符（⏹ ✅ 🔴 🟡 ⚠️）。

---

## 7. 单文件报告导出

会话结束后可生成 `report.html`：把整场讨论（人设、发言、台账、最终文档）
打包成**一个自包含的 HTML 文件**，内联全部样式与数据，不含任何外部请求。

用途：把这一个文件发给同事，他就能看到完整讨论过程。

> 这一条是**可选功能**，v0.1 不实现，但数据结构上已经支持
> （`transcript.jsonl` 自包含全部事件）。
