### demo_server.py

改前端时不必真跑一次头脑风暴（那要 4 分钟和几毛钱）：

```bash
python3 tools/demo_server.py            # 起服务并打开浏览器
python3 tools/demo_server.py --port 9000 --no-browser
```

它注入一段**写死的合成事件序列**，并伪装成一个提案工作台 ——
清单里同时有「进行中 / 已完成 / 未跑完」三种提案，所以列表、详情、
设计文档、以及"连接结束了但讨论没收口"这条路径都能看到，结果完全可复现。
`tests/test_server.py::TestDemoFixture` 会核对它与事件协议没有脱节，
也会核对它实现的是真的 `ProposalApi` 那套接口。

它**不是产品的一部分** —— 只是给改前端的人省时间。

## 为什么需要它

[ADR 0001](../docs/adr/0001-python-stdlib-single-entry.md) 承诺了
"零第三方依赖、clone 即跑"。但"clone 即跑"仍然需要用户先有整个目录树。

单文件打包把这件事推到极致：**用户可以下载一个 `.py` 文件直接运行**，
不需要 git、不需要目录、不需要任何安装。这对"偶尔用一次的小工具"是很实际的收益。

## 打包方式

无构建工具，就是一个纯文本拼接脚本：

```
dist/sparky.py
├── #!/usr/bin/env python3
├── 各模块源码（按依赖顺序拼接，去掉互相 import 的行）
├── WEB_ASSETS = {
│       "index.html": """...""",
│       "app.js":     """...""",
│       "style.css":  """...""",
│   }
└── if __name__ == "__main__": main()
```

`server.py` 在打包模式下从内存字典读前端资源，在正常模式下从磁盘读 ——
两种情况共用同一套事件逻辑。

## 验收标准（M4）

- [ ] 产出的 `dist/sparky.py` **零第三方依赖**，可在干净环境直接运行
- [ ] 前端资源已内联，断网可用
- [ ] 行为与包模式**完全一致**（同一份输入产出同一份文档）
- [ ] 打包脚本本身只用标准库
- [ ] 资源缺失时报错，**不产出半成品**

## 失败模式

源码目录结构与脚本预期不符（如模块被重命名）→ 报错退出，不产出残缺文件。

宁可打包失败，也不要产出一个"看起来能跑但少了个模块"的单文件 ——
用户会把它拷到别的机器上，然后在那里遇到一个无法理解的错误。
