# 示例

这里放**真实跑出来的完整会话**。一句输入进去，一份文档出来，
中间发生了什么全部可查 —— 这是本项目最有说服力的东西。

## 现有样例

### [`01-podcast-transcriber/`](01-podcast-transcriber/) —— M1 时期，**无讨论阶段**

输入是 `我想做一个给播客自动生成章节和文字稿的小工具，本地跑，不要云服务`，
产出一份 **38542 字**、通过全部 9 项合规校验的设计文档。

18 次调用 · 156976 token · 约 4 分 40 秒。

### [`02-podcast-with-debate/`](02-podcast-with-debate/) —— M2，**完整讨论**

**同一个输入**，跑完六个阶段：专家们真的吵了 3 轮，
台账 12 项分歧（2 被说服解决 / 9 降级为取舍 / 1 未决）。

25 次调用 · 190849 token · 约 4 分 20 秒 · 产出 36916 字。

**这两份对比着读最有价值**：同样的输入，差别只在"有没有交锋"。
样例一的第 5 节是空的（没有取舍可登记），样例二有 9 行，
每行都写着「什么条件下该反过来选」。

| 文件 | 看什么 |
|---|---|
| `01/input.md` | 用户当时只说了什么、以及**没说什么** |
| `01/design.md` | M1 产物：独立调研的并列，未经检验 |
| `02/ledger.json` | ★ 分歧台账全量：当事人、双方立场、逐轮交锋、最终状态 |
| `02/rounds/r*.json` | ★ 每一轮的发言，可以看清讨论怎么推进 |
| `02/design.md` | ★ M2 产物：含真实取舍台账与未决问题 |
| `02/notes.md` | ★ 诚实记录：这次运行证明了什么、**不能**证明什么 |
| `*/transcript.jsonl` | 事件溯源日志 |
| `*/notes.md` | 三条告警在真实运行中各自触发的过程 |

`02/notes.md` 里那条未决问题值得单独看：反方用**方法论层面**的攻击
（"一个不可失败的成功标准，测不出任何东西"）拆开了一个看起来已经想清楚的
验收标准，而且**没有伪造结论** —— 这正是本工具存在的意义。

## 样例要证明的三件事

1. **`01` 证明能产出一份合格的文档** —— 通过
   [output-spec.md](../docs/output-spec.md) §3 的全部 9 项检查 ✅

2. **`02` 证明讨论阶段真的在工作** —— 分歧台账非空、定向加轮只召集当事双方、
   §5/§8 与台账条数严格相等 ✅

3. **`03` 证明维度抽取是从问题长出来的，不是套模板** ——
   两个样例的维度集合重合度应该**很低**。
   如果重合度很高，说明"现场生成维度"这个设计没有真正生效，
   应该去改 [ADR 0002](../docs/adr/0002-persona-generation-over-fixed-cast.md)

## 一条诚实要求

样例**不许挑选**。"跑得最好的那三次"作为样例是在做宣传，不是做验证。

如果某个样例产出了质量差的文档，**照样收录**，并在 `notes.md` 里写清
差在哪、怀疑是哪个环节的问题。失败样例对本项目的价值远高于成功样例 ——
[design.md](../docs/design.md) §11 列的那些未决问题，
正是靠这类样例才能被解决。

此外，每个样例的 `notes.md` 必须有一节写清**这次运行不能证明什么**。
`01` 的 §3 就是：没有讨论阶段、没有外部检索、样本量为 1。
