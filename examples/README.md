# 示例

这里放**真实跑出来的完整会话**。一句输入进去，一份文档出来，
中间发生了什么全部可查 —— 这是本项目最有说服力的东西。

## 现有样例

### [`01-podcast-transcriber/`](01-podcast-transcriber/) ✅

输入是 `我想做一个给播客自动生成章节和文字稿的小工具，本地跑，不要云服务`，
产出一份 **38542 字**、通过全部 9 项合规校验的设计文档。

18 次 LLM 调用 · 156976 token · 约 4 分 40 秒。

| 文件 | 看什么 |
|---|---|
| `input.md` | 用户当时只说了什么、以及**没说什么** |
| `design.md` | ★ 最终产物 |
| `brief.json` | S0 抽出的 8 个维度（7 个用户没提过） |
| `personas.json` | 7 位专家的人设，含反方的立场/偏见/盲点 |
| `stances/` | 每个人的独立调研备忘（含优点、缺点、让步条件、依据） |
| `transcript.jsonl` | 事件溯源日志，28 条事件 |
| `notes.md` | ★ **诚实记录**：这次运行证明了什么、**不能**证明什么 |

`notes.md` 里记了三条告警在真实运行中各自触发一次的过程 ——
它们分别是 JSON 全角逗号重试、人数裁剪保护反方、摘要超长重写。
这三条都是实现过程中踩出来的真实问题，不是设想出来的。

## 样例要证明的三件事

1. **`01` 证明能产出一份合格的文档** —— 通过
   [output-spec.md](../docs/output-spec.md) §3 的全部 9 项检查 ✅

2. **`02` 证明维度抽取是从问题长出来的，不是套模板** ——
   两个样例的维度集合重合度应该**很低**。
   如果重合度很高，说明"现场生成维度"这个设计没有真正生效，
   应该去改 [ADR 0002](../docs/adr/0002-persona-generation-over-fixed-cast.md)

3. **`03` 证明信息面隔离确实产生了真实分歧** ——
   对比固定评审团与现场生成，看分歧质量是否有差异

## 一条诚实要求

样例**不许挑选**。"跑得最好的那三次"作为样例是在做宣传，不是做验证。

如果某个样例产出了质量差的文档，**照样收录**，并在 `notes.md` 里写清
差在哪、怀疑是哪个环节的问题。失败样例对本项目的价值远高于成功样例 ——
[design.md](../docs/design.md) §11 列的那些未决问题，
正是靠这类样例才能被解决。

此外，每个样例的 `notes.md` 必须有一节写清**这次运行不能证明什么**。
`01` 的 §3 就是：没有讨论阶段、没有外部检索、样本量为 1。
