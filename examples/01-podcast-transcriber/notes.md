## 1. 这次运行最有价值的地方：三条告警各自触发了一次

本次会话产生了 **3 条 warning**，恰好对应三套不同的机制。
它们同时说明了「这些机制是必要的」和「它们是有效的」。

### 告警一：`json_parse_retry` —— S1 展开人设

```
S1 组阁·展开人设：第 1 次输出不是合法 JSON
（Expecting ',' delimiter，位置 5728），已附加纠正提示后重试。
```

**原因**：中文模型在 JSON 的**结构位置**写出了全角逗号
（`"甲"，"乙"` 而不是 `"甲", "乙"`）。
`response_format: json_object` 拦不住它 —— 它不做约束解码。

**处理**：附加纠正提示后重试一次，第二次成功。
**没有**做的是：把全角逗号全局替换成半角 —— 那会连字符串**内容**里的
中文标点一起改掉，属于静默篡改。

### 告警二：`panel_size_truncated` —— 8 人裁到 7 人

```
人数 8 超过上限 7，已裁掉 1 人：['陆鹤鸣']（优先裁掉维度最少的非反方成员）
```

**这里曾经有一个真实 bug**：早先的裁剪实现是「从尾部一刀切」，
而模型把**唱反调者排在最后一位**时就会被切掉，随后校验直接报
「专家组里没有唱反调者」，整场运行作废。

**现在的裁剪有三条优先级**：不裁反方 → 优先裁维度最少的 → 不制造维度空洞。
本次裁掉的是「陆鹤鸣」（贡献维度最少的非反方成员），反方骆一鸣被保住。

### 告警三：`summary_overlong` —— 摘要 487 字，重写一次

```
摘要 487 字，超过上限 400 字，正在要求模型重写（第 1 次）。
```

**为什么值得重试而不是直接判废**：一次真实会话曾因摘要 456 字（超 14%）
把整场 16 次调用判废，代价与收益完全不成比例。

**为什么是重写而不是截断**：截断会切在句子中间，而且会**替模型决定**
丢掉哪些信息。要求它自己压缩一遍，既不篡改内容，也能真的保住信息。
