# 样例输入

```
我想做一个给播客自动生成章节和文字稿的小工具，本地跑，不要云服务
```

就这一句。没有说产品形态、没有说技术栈、没有说支持哪些平台、
没有说要多快、没有说转写质量要求。

这正是 Sparky 要处理的处境：**想做个东西，但完全没有头绪。**

---

## 这个输入里，用户实际只说清了两件事

| 说清了 | 没说的（由 S0 推断出来） |
|---|---|
| 做什么：播客 → 章节 + 文字稿 | 模型体积与内存 |
| 硬约束：本地跑、不用云 | 长音频怎么处理 |
| | 章节按什么切 |
| | 转写质量与速度怎么权衡 |
| | 说话人要不要区分 |
| | 产物是什么形态、怎么分发 |

S0 一共推出 8 个设计维度，其中 **7 个是用户原话里没有的**。
这就是「不知道要考虑什么」这个困难的解法 —— 维度是从问题里推出来的，
不是从一张固定清单里套的（见 [ADR 0002](../../docs/adr/0002-persona-generation-over-fixed-cast.md)）。

---

## 复现方式

```bash
export DEEPSEEK_API_KEY=sk-...
python3 -m sparky "我想做一个给播客自动生成章节和文字稿的小工具，本地跑，不要云服务"
```

本次运行：**18 次 LLM 调用 · 156976 token · 约 4 分 40 秒**（见 `design.md` 附录 D）。
